# V1.30 Release Notes — 2026-09-21

## 版本主题：Governance 审计可检索 + CSV 导出 + 保留策略 TTL（审计全生命周期闭环）· 市场雷达 09-21

> 一句话：V1.29 解决了「审计落库」，V1.30 解决「审计怎么查、怎么导出、怎么合规清理」——把审计从存储升级为**可运营的合规取证资产**。

---

## 变更内容

### 1. 审计多条件检索 `search(Query)`（mcp-governance，核心）
- **背景**：V1.29 的 `recent(limit)` 只能「最近 N 条」，企业安全团队要的是
  「上周谁用 `finance_transfer` 被拒了」「某调用方今天触发了几次审批」这类过滤查询；
- **实现**：`McpGovernanceAuditSink` 新增 `Query` 记录（tool / caller / decision / tier / from / to / limit，全字段可空=不过滤）+ `search(Query)`：
  - **JDBC 实现**：动态 WHERE 全参数绑定，方言无关（H2/MySQL/MariaDB/PG/SQL Server），
    时间范围用 epoch millis 比较，`ORDER BY ts DESC, seq DESC` 后内存截断（与 V1.29 同款方言无关策略）；
  - **内存实现**：同语义过滤，供零依赖场景使用；
  - limit 自动 clamp 到 [1, 1000]，防滥用。
- **管理 API**：`GET /api/admin/governance/audit` 升级为支持
  `?tool=&caller=&decision=&tier=&from=&to=&limit=` 多条件过滤（旧的无参调用完全兼容）。

### 2. 审计 CSV 导出 `/audit/export`（SIEM 导入 / Excel 取证 / 监管报送）
- **背景**：落库的审计要能「交出去」——Sumo Logic 类 SIEM、审计师 Excel 复核、监管报送都需要结构化导出；
- **实现**：`GET /api/admin/governance/audit/export` 返回 RFC 4180 CSV：
  - 首行 UTF-8 BOM（Excel 直接打开中文不乱码）；
  - 字段含逗号/引号/换行时自动转义（防 CSV 注入）；
  - 列：timestamp, tool, tier, caller, decision, approvalId, message；
  - 支持与检索相同的过滤参数。
- **示意**：
  ```bash
  curl -s "http://localhost:8081/api/admin/governance/audit/export?tool=finance_transfer&limit=1000" \
    -H "Authorization: Bearer $TOKEN" > audit-finance.csv
  ```

### 3. 保留策略 TTL 清理 `/audit/prune`（合规生命周期）
- **背景**：审计是合规资产，但也是隐私负担——GDPR「数据最小化」要求定时清理，
  企业需要「保留 90 天 / 180 天」的可执行策略，而不是无限膨胀；
- **实现**：`McpGovernanceAuditSink.deleteBefore(Instant)`：
  - **JDBC 实现**：`DELETE FROM table WHERE ts < ?`（全参数绑定、方言无关），
    返回删除条数并打日志；
  - **内存实现**：`removeIf` 同语义；
  - 管理 API `POST /api/admin/governance/audit/prune?retentionDays=90`
    → 清理早于 N 天的历史事件，返回 `{retentionDays, cutOff, deleted}`；
  - 可与 cron/定时任务配合实现「每月 1 号自动清理」。
- **示意**：
  ```bash
  curl -s -X POST "http://localhost:8081/api/admin/governance/audit/prune?retentionDays=90" \
    -H "Authorization: Bearer $TOKEN"
  # {"retentionDays":90,"cutOff":"2026-06-23T13:00:00Z","deleted":1234}
  ```

## 部署配置速览

```yaml
mcp:
  enterprise:
    governance:
      audit:
        store: jdbc          # V1.29 审计落库（检索/导出/清理均基于落库数据）
        table: mcp_governance_audit
        init-schema: true
```

**审计全生命周期闭环（V1.26 → V1.30）**：
- V1.26 审计事件产生 → V1.29 落库可查 → **V1.30 过滤检索 + CSV 导出 + TTL 清理**
- 对应企业安全团队的完整问题链：「**发生了什么 → 在哪查 → 怎么交出去 → 留多久**」
