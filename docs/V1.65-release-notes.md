## 🔧 工程增量说明（本次真实新增代码）

`examples/monitor-alert-rules/` 把 V1.64 的情报转成**检测能力**，并刻意分两层：

| 层 | 组件 | 能检测 | 不能检测 |
| --- | --- | --- | --- |
| 应用内实时 | `McpSecurityAlertRules.java` → `McpAlertService.addRule()` | 凭据盗刷、工具枚举爆发、拒绝风暴、慢速外传、静默高吞吐、宕机前兆（`ToolMetrics` 六字段） | 出站白名单、子进程、凭据访问、令牌受众 |
| 集群 / SIEM | `mcp-security-alerts.yml` → Prometheus | 上述四类**非调用指标** + 跨实例聚合、长时窗趋势 | 进程内秒级反应 |

> ⚠️ **诚实标注**：`mcp-monitor` 当前导出的是 `mcp_tool_*` / `mcp_gateway_*` / `mcp_build_info`，**尚未导出 `mcp_security_*`**。本目录定义的是埋点契约与规则，需由网关过滤器在拒绝分支补埋点；README 给出最小 Micrometer 示例并明确「**审计优先于告警**」（告警可被抑制，append-only 审计不能丢）。
> **构建安全**：示例位于 `examples/`，不在 `pom.xml` 的 `<modules>` 中，不参与 Maven reactor 与 CI 构建，零构建风险。

**交叉验证（今日最值钱的一条）**：11-05 ChatCLI 修复公告一次修掉的 7 类相邻传输缺陷（canonical URL 作唯一 resource indicator、SSE 同源、拒绝跨源/降级重定向、metadata 必须声明 issuer + HTTPS、`resource_metadata` 仅同源跟随、发现文档大小上限），与 V1.64 交付的 `examples/governance-hardening/` 覆盖条目几乎一一对应 —— **昨晚写的参考实现，今早被第三方安全公告逐条背书**，可直接写进 11-13 报名的「可演示案例」。
