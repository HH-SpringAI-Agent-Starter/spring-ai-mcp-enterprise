# V1.17 发布说明 —— A2A 网关 OAuth2 Bearer 强制鉴权（RFC 6750）+ mcp-auth 令牌互通

> 发布日期：2026-09-02
> 核心主题：**让 A2A 网关从"声明鉴权方案"升级为"强制校验令牌"** —— 完成 mcp-auth 深度打通的第二块拼图（V1.16 只声明 securitySchemes，V1.17 真正校验 Bearer JWT）。
> 版本基线：V1.16（A2A SSE 流式 + securitySchemes 声明）→ V1.17

---

## 一、为什么做 V1.17

**V1.16 已在 Agent Card 声明 securitySchemes（api-key / oauth2），但 oauth2 只是"声明"，网关并未真正校验 Bearer 令牌——企业客户一眼就能看穿这是"假安全"：**

1. **市场信号**：
   - A2A v1.0 GA 规范中，**认证信任模型 = HTTPS 基线 + OAuth 2.0 流程 + 签名 Agent Card 三层**，OAuth2 是 agent-to-agent 授权的核心（亚马逊 Bedrock AgentCore、微软 Azure AI Foundry 均已落地）。
   - 8-09 行业综述明确："A2A supports OAuth 2.0/OIDC at parity with OpenAPI security schemes"——**声明 oauth2 却不校验 = 供应链漏洞级事故**。
   - 招聘 JD 高频词持续点名 "**OAuth2/JWT / token 管理**"（Bitrock $120-150K、CriticalRiver、Skm Group €54-120K、Photon/Citi OAuth2+OWASP 全栈要求）。
   - 昨天市场雷达（09-01）给出的 V1.17 待办第一条就是：**mcp-auth 深度打通——OAuth2 Client Credentials 实际令牌交换 + 网关强制校验（不止声明）**。

2. **技术判断**：mcp-auth 模块已有完整 OAuth2 Token 端点（Client Credentials 签发 JWT）+ JwtTokenProvider（HS256 校验），缺的只是一个**消费方**：A2A 网关按 `Authorization: Bearer <JWT>` 校验 mcp-auth 签发的令牌。密钥同值即互通，无新增基础设施。

3. **结论**：V1.16 把 A2A 侧"说清楚要什么鉴权"，V1.17 把"真正拦下来"——声明与强制校验一致，可对外宣称 **OAuth2-secured A2A gateway（RFC 6750）**。

## 二、新增内容

### 1. A2A 网关三种鉴权模式（mcp-integrations/mcp-a2a）

| 模式 | 配置 | 校验方式 | 适用场景 |
| --- | --- | --- | --- |
| `none` | （默认） | 不鉴权，可置于网关 API Key 之后 | 内部/开发环境 |
| `api-key` | `mcp.enterprise.a2a.api-key` 非空 | `X-A2A-Key` 请求头 | 轻量服务间调用 |
| `oauth2` | `mcp.enterprise.a2a.jwt-secret` 非空 | `Authorization: Bearer <JWT>`（RFC 6750） | 企业级，与 mcp-auth 令牌互通 |

**模式推导优先级**（`McpA2aProperties.resolvedAuthMode()`）：
1. `security-scheme` 显式声明（oauth2 / api-key / none）→ 尊重声明，强制校验与声明一致
2. `jwt-secret` 非空 → `oauth2`
3. `api-key` 非空 → `api-key`
4. 否则 → `none`

### 2. 新类：A2aJwtTokenValidator

- HS256 JWT 校验器，**密钥派生规则与 mcp-auth `McpJwtTokenProvider` 完全一致**（不足 32 字节补足到 32 字节）
- `mcp.enterprise.a2a.jwt-secret` 与 `mcp.auth.jwt-secret` 同值时，mcp-auth OAuth2 Client Credentials 端点签发的 access_token 直接通过 A2A 网关校验 → **"mcp-auth 发证、A2A 网关验证"完整 OAuth2 闭环**
- 校验语义：签名 + 过期（ExipiredJwtException 单独区分）+ 格式容错，失败统一返回 null（401）

### 3. A2aRpcController 鉴权升级

- `authorized()` 按推导模式分派：none 放行 / api-key 校验 X-A2A-Key / oauth2 校验 Bearer
- 未授权响应体错误消息按模式区分：
  - oauth2 → `"Authentication required (Authorization: Bearer <JWT> - RFC 6750)"`
  - api-key → `"Authentication required (X-A2A-Key)"`
- 所有端点统一走该逻辑：`agent-card` / `/.well-known/agent-card.json` / `rpc` / `rpc/stream`(SSE) / `health`
- `health` 增加 `authMode` 字段输出当前鉴权模式
- **顺手修复**：未授权 JSON-RPC 响应使用 `LinkedHashMap` 替代 `Map.of`（`Map.of` 不允许 null value，`"id": null` 会抛 NPE——历史潜在 bug，被本次鉴权测试暴露）

### 4. 配置示例

```yaml
mcp:
  enterprise:
    a2a:
      enabled: true
      # V1.17: OAuth2 Bearer 强制鉴权（与 mcp-auth 同密钥即互通）
      jwt-secret: ${MCP_A2A_JWT_SECRET:}
      security-scheme: oauth2     # 可选：显式声明；默认随 jwt-secret 自动推导
      oauth2-token-url: https://your-host/api/auth/oauth2/token   # Agent Card 声明的令牌端点
```
