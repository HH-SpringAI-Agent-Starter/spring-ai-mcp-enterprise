> 一句话：**让 HITL 从「单机承诺」升级为「集群承诺」** —— 审批队列落库，
> 多实例部署下审批-消费跨副本可见，重启/滚动发布不丢审批记录；同步完成 09-19 市场情报。

## 变更内容

### 1. 新增 `JdbcApprovalStore`（mcp-governance，核心）
- **背景**：V1.26 的 `InMemoryApprovalStore` 把审批队列放在单个 JVM 内存里——
  单实例演示没问题，但企业多实例拓扑（K8s 多副本/滚动发布）下，
  审批人批准了一条请求，消费方请求可能落到另一个实例 → 状态不可见，HITL 闭环断裂；
- **实现**：审批请求持久化到单表 `mcp_approval_requests`（可自定义表名）；
  保持 V1.22 `JdbcSkillRegistryStore` 的设计约束 —— **方言无关**（只用
  `CREATE TABLE IF NOT EXISTS`/`INSERT`/`SELECT`/`UPDATE` 绑定参数，
  避开 MERGE；H2/MySQL/MariaDB/PostgreSQL/SQL Server 直接可跑）、
  参数以 JSON 文本落库、时间戳 epoch millis；
- **语义**：**读穿式**（get/list 每次查库，无本地缓存、无一致性窗口）；
  写入 fail-soft（记 WARN 并抛给上层——审批是 Fail-closed 语义，宁可报错不可错放）；
  一次性令牌 `CONSUMED` 状态落库 → **防重放从单机承诺升级为集群承诺**；
- **复用**：`ApprovalRequest` 新增包私有还原构造器（保持 id/createdAt/expiresAt 与库一致），
  无反射、无 `toMap` 序列化破坏。

### 2. 自动配置 store 选择（`approval.store=memory|jdbc`）
- `mcp.enterprise.governance.approval.store=jdbc` + classpath 有 `JdbcTemplate` →
  自动创建 JDBC store 并幂等建表（`init-schema` 可关，表名 `table` 可配）；
- 配置了 `store=jdbc` 但没有数据源 → 打 WARN 回退内存实现（进程不挂，可用性优先）；
- 未配置 → 维持 V1.26 内存行为（零依赖，默认值不变）。

### 3. 测试（35 个全绿，新增 7 个）
- 新增 `JdbcApprovalStoreTest`：save/get 往返（含脱敏参数 JSON 特殊值）、
  list 状态过滤 + 创建时间倒序、update 状态流转持久化、count、缺省 null、
  参数往返（长字符串/浮点/布尔/嵌套 List）、TTL 往返——全部挂在 H2 内存库上验证；
- 既有 28 个 governance 测试保持全绿（`mvn -pl mcp-governance test` 通过）。
