# V1.31 Release Notes — 审计 × 链路追踪关联（W3C traceparent）

> 发布日期：2026-09-22 ｜ 版本：1.1.0-SNAPSHOT → 1.1.0（governance 模块）
> 主题：**让治理审计事件与 OpenTelemetry 分布式调用链（W3C traceparent）双向打通**

---

## 一句话

V1.26~V1.30 回答了审计的「记录 / 存储 / 检索 / 保留」，V1.31 回答 **「这条审计属于哪次调用链」**：
每次治理判定自动携带 `traceId`/`spanId`，事故复盘从"时间戳±模糊猜"升级为"traceId 秒级精确回溯"。

## 新增内容

### 1. `TraceContext` 工具类（mcp-governance，零外部依赖）
- 严格解析 W3C `traceparent`（`version-traceId-spanId-flags`，仅支持 version-00）；
- 四级兼容策略：`traceparent` 头 → `X-Request-Id` 头 → SLF4J MDC `traceId` → UUID 兜底；
- 项目已接入 micrometer-tracing / Spring Boot Tracing 时自动识别其 MDC 值，**无需任何改造**；
- 公共常量 `HEADER_TRACEPARENT` / `HEADER_X_REQUEST_ID` / `ATTR_TRACE_ID` / `ATTR_SPAN_ID`。

### 2. 审计事件扩展（`McpGovernanceAuditSink.Event`）
- 新增 `traceId`（32 位 hex）+ `spanId`（16 位 hex）字段，`toMap()` 有值才输出；
- 保留 V1.26~V1.30 兼容构造器，存量调用方零改动。

### 3. 检索与导出支持 traceId
- `Query` 新增 `traceId` 过滤条件（含兼容构造器）；
- `GET /api/admin/governance/audit?traceId=xxx` 按 trace 回溯一次调用链的全部治理判定；
- `GET /api/admin/governance/audit/export?traceId=xxx` CSV 导出新增 `traceId` 列（SIEM/取证直连）。

### 4. JDBC 持久化升级（`JdbcGovernanceAuditSink`）
- `mcp_governance_audit` 表新增 `trace_id VARCHAR(32)` / `span_id VARCHAR(16)` 列；
- `initSchema()` 幂等：新库直接建两列；**老表自动 `ALTER TABLE ADD COLUMN` 升级**（数据库不支持则忽略，保持兼容）；
- 查询/导出/检索/保留策略全部兼容新列，`count()` 不受影响。

### 5. 治理过滤器透传（`McpGovernanceFilter`）
- 请求到达时解析 trace 上下文并写入 request attribute（`ATTR_TRACE_ID`/`ATTR_SPAN_ID`），下游 Filter/拦截器可直接复用；
- 审计事件携带完整 trace 信息落库。

## 使用方式

```bash
# 1) Agent/网关透传标准头即可（无需改服务端配置）
curl -X POST http://localhost:8081/api/mcp/v2/message \
  -H "Authorization: Bearer $MCP_API_KEY" \
  -H "traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"db_query","arguments":{}}}'

# 2) 按 traceId 回溯一次调用链的全部治理判定
curl "http://localhost:8081/api/admin/governance/audit?traceId=4bf92f3577b34da6a3ce929d0e0e4736"

# 3) CSV 导出（携带 traceId 列，喂 SIEM）
curl -H "Authorization: Bearer $MCP_ADMIN_KEY" \
  "http://localhost:8081/api/admin/governance/audit/export?traceId=4bf92f3577b34da6a3ce929d0e0e4736"
```

## 为什么现在做这个（市场信号）

- 2026 MCP 岗位 JD 中 **OpenTelemetry（traces/metrics/logs）成为高频硬技能**（如 Intellias Python MCP Engineer、FlairMinds MCP Developer 均明确要求）；
- 企业安全团队事故复盘的标准答案是「一条 trace 看全链路」，审计与 trace 脱钩 = 审计价值减半；
- 零依赖实现，避免为「对齐 OTel」引入 micrometer-tracing，保持模块轻量，也方便买家在现有 APM 栈上即插即用。
