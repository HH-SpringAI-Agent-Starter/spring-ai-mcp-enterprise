## 二、为什么做这些

1. **Spring AI Alibaba 1.0 GA（2026-10）正式发布**，企业级 MCP 方案 = Nacos MCP Registry + Higress AI 网关，**与本框架 `mcp-registry`+`mcp-gateway` 定位同款**。本版本把框架重新定位为官方方案的"**安全治理增强层**"，并给出可运行的 GA 示例。
2. **央企/国企双招标点名"MCP 注册"**（长庆油田 130 万 10-16 截标、航空工业 ZC26G280436 10-20 截标）→ 补齐可直接套用的投标技术方案模板，把开源影响力转化为订单。
3. **Upwork 官方 MCP Server 已成接单基础设施** → 框架 repo 即"生产级作品集"，本版本强化 README 招聘/招标区块以承接流量。

## 三、代码改动范围与风险评估

- **无破坏性变更**：主 reactor 21 模块未改动；新增示例置于 `examples/`（不在父 `<modules>`），不影响 CI。
- **未触碰** `mcp-integrations/mcp-alibaba`（其依赖 `spring-ai-alibaba-starter` 里程碑版 `1.0.0-M6.1`，保持现状以免破坏既有构建）；GA 适配以独立示例呈现，待验证后择机升级主模块。
- **未本地 Maven 构建**（自动化环境不构建，留给 CI / 本地校验）。

---

## 四、对齐的模块能力（投标/接单话术底座）

- `mcp-registry`：Skill Registry（语义化版本 + 灰度 + 一键回滚 + JDBC 持久化）
- `mcp-gateway`：联邦网关（命名空间隔离 + 统一鉴权 + 一键下线）
- `mcp-governance`：RBAC/审计 JDBC 可取证/HITL/限流/脱敏 + W3C traceparent 链路追踪（66 测试全绿）
- `mcp-alibaba`：通义千问/DashScope 原生兼容（GA 示例补齐）
- `mcp-tenant` / `mcp-monitor`：多租户隔离 + Prometheus/Grafana 可观测
