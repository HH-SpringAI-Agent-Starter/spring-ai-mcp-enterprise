## 一、本期结论

V1.69 把治理起点推回「工具注册进来的那一刻」。本期 11-10~11-12 的实时情报把问题再推进一层：**负责审批这些工具的注册中心自己，被当成了提权入口**；与此同时，国内买方第一次把「MCP 封装接入」写成运维项目的正式目标。

## 四、口径与诚实标注

- ⚠️ **版本口径**：公开来源对 AWS 两洞修复版本表述不一致（一说 privesc 影响 `1.0.9–1.24.7`、修于 `1.25.0`／6-27；另一说受影响至 `1.34.0`、SSRF 修于 `1.35.0`／10-29，GHSA 均 11-11 才公布）。可自洽读法为两洞分别修复、GHSA 延迟披露；**版本级符合性一律以 AWS 官方公告 / GHSA 原文为准**，本期不做断言。
- ⚠️ **本框架不受上述 CVE 直接影响**（未依赖 AWS / Microsoft 的 registry 与 gateway 组件）；Microsoft `109492` 标注 `Not known to be exploited`。
- ⚠️ 广发四份均为**供应商预征集 ≠ 采购邀请**；13327 **截止时间未在检索到的正文中呈现**，「第四份」为编号序列推断。本项目**不成立 3 年、无企业主体、不满足原厂/授权代理 / 2 个运维平台案例 / 广州本地团队 / 注册金 500 万 / 税务证明**，**无商业合同、无中标、无金融案例、无等保测评 / 算法备案** → 只能作联合体技术分包，禁虚构材料。
- ⚠️ 13327 应答包**明确不承担**第 2（代码级排障 / 调用图）、3（运维知识图谱）、5（运维技能本体）条目标；`mcp_security_*` 仍在 `examples/` 层、`mcp-monitor` 主模块未内置导出，接入工作量须如实计入排期。
- ⚠️ 新示例仍是**参考实现，未接入 `mcp-registry` 主模块**；主机判定为字面量检查、不做 DNS 解析，需与 `McpResolvedIpGuard` 叠加才能覆盖 rebinding；跨主机重定向默认拒绝是保守策略选择；`fingerprint` 只覆盖上游 URL。
- ⚠️ 全部报价为**卖方销售页公开价 / JD 标价，非成交价**；Upwork「近 5,000 万 agent requests」是平台请求量，**≠ MCP 通道收入**；行业数字（1,314 智能体 / 404 技能 / 34 篇案例）来自 11-12 媒体引用半年报，未逐份回查原始财报；自媒体「岗位 +217% / +455%」「初级 40–60 万年薪」口径不明，**未采信**。
- ⚠️ Spring AI 2.0 **未执行升级**；`McpToolAnnotationGate` 接入主模块仍未做。
