# V1.18 发布说明 —— A2A Signed Agent Card（签名 Agent Card，A2A v1.2 供应链安全基线）

> 发布日期：2026-09-03
> 核心主题：**把 Agent Card 从"自证的能力声明"升级为"可加密验证的能力凭证"** —— JWS 签名卡片，防 DNS 劫持 / 中间人篡改能力发现
> 版本基线：V1.17（A2A 网关 OAuth2 Bearer 强制鉴权，RFC 6750）→ V1.18

---

## 一、为什么做 V1.18

**V1.15→V1.17 已解决"编排器如何安全地调用本网关"（X-A2A-Key / Bearer JWT），但还缺最后一块拼图：编排器如何确认"这张 Agent Card 真的是你发布的"？**

1. **市场信号（今日雷达 09-03）：**
   - A2A v1.0 GA（2026-04，Linux Foundation）官方特性清单明确包含 **Signed Agent Cards for cryptographic identity verification**（JWS + JSON Canonicalization）——签名卡片已成为协议级标准能力，不签名 = 落后于规范。
   - BeyondScale《A2A Security: CISO Guide》（2026-04）将 **"Agent cards are unsigned by default, creating spoofing and prompt injection vectors"** 列为五大攻击模式之首——**签名 Agent Card 是企业级部署的强制控制项**，与 mTLS、OAuth2 并列。
   - 09-02 雷达 V1.18 待办第一条就是 Signed Agent Card 落地，与本次实现完全对齐。

2. **攻击场景（为什么"签名"不是可选项）：**
   - 攻击者注册相似域名，发布伪造的 `/.well-known/agent-card.json`，宣称自己是指数计算/财务合规工具；
   - 编排器动态发现能力时未校验卡片来源 → 把真实任务负载路由到恶意服务器（BeyondScale 攻击模式 #1：Agent Card Spoofing & Impersonation）；
   - 不签名 = 供应链漏洞；签名 = 编排器可验证"该卡片确实来自持有密钥的一方"。

3. **技术判断**：V1.17 已有 `A2aJwtTokenValidator`（HS256，密钥派生与 mcp-auth 一致）。签名 Agent Card 复用同一把密钥与派生规则即可实现——**"mcp-auth 发证 + 网关验签 + Agent Card 签名"三方同钥闭环**，零新增基础实施。

## 二、新增内容

### 1. `A2aAgentCardSigner` —— JWS 签名器 / 校验器（mcp-integrations/mcp-a2a）

- **JWS Compact Serialization（RFC 7515）**：`base64url(header) . base64url(canonicalCardJson) . base64url(HMAC-SHA256)`
- **规范化（Canonical JSON）**：Jackson `ORDER_MAP_ENTRIES_BY_KEYS` 确定性序列化，跨语言客户端可复现同一签名输入
- **密钥派生与 mcp-auth `McpJwtTokenProvider` 完全一致**：secret < 32 字节以零字节补齐（HS256 最小密钥长度）→ 与 mcp-auth / A2A 网关令牌互通
- **防算法混淆**：header 非 `HS256`（如 `alg=none`）一律拒绝
- **常量时间比较**：`MessageDigest.isEqual` 防时序侧信道
- 客户端一键校验：`A2aAgentCardSigner.verify(jws, secret)`（静态方法，无需构造签名器）

### 2. `SignedAgentCard` 信封（响应体）

```json
{
  "agentCard": { "name": "...", "skills": [...] },
  "signature": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXUyIsImtpZCI6Im1jcC1hMmEtMSJ9.eyJ... .<sig>",
  "algorithm": "HS256",
  "keyId": "mcp-a2a-1",
  "signedAt": "2026-09-03T13:30:00Z"
}
```

### 3. 端点行为升级

| 端点 | V1.17 及以前 | V1.18（配置签名密钥后） |
| --- | --- | --- |
| `GET /a2a/agent-card` | 裸 Agent Card | SignedAgentCard 信封 + `X-Agent-Card-Signature` 响应头 |
| `GET /.well-known/agent-card.json` | 裸 Agent Card | 同上（RFC 8615 标准发现路径） |
| `GET /a2a/agent-card/verify` | — | 新增：自验证结果（valid/algorithm/keyId/signedAt），demo + 巡检脚本用 |
| `GET /a2a/health` | status/agent/skills/streaming/authMode | 新增 `signedCard` / `cardKeyId` 字段 |

- 签名异常时**防御性退回原始卡片**（fail-open），不影响服务可用性
- 未配置签名密钥时行为与 V1.17 完全一致（向后兼容）

### 4. 配置（mcp-server/application.yml）

```yaml
mcp:
  enterprise:
    a2a:
      enabled: true
      # V1.18: Signed Agent Card 签名密钥——非空时 agent-card 返回签名信封
      # 与 mcp.auth.jwt-secret 同值 → "同一把密钥：发证 + 验签 + 卡片签名"完整闭环
      card-signing-key: ${MCP_A2A_CARD_SIGNING_KEY:}
      card-key-id: ${MCP_A2A_CARD_KEY_ID:mcp-a2a-1}
```

## 三、测试

新增 `A2aAgentCardSignerTest`（9 个用例），覆盖：

- ✅ JWS 三段结构 + header 声明（alg=HS256 / typ=JWS / kid）
- ✅ 往返验证通过 + 规范化 JSON 可反序列化回 `A2aAgentCard`
- ✅ 篡改签名拒绝
- ✅ 错误密钥拒绝
- ✅ 静态 `verify(jws, secret)` 与实例校验一致（客户端路径）
- ✅ 确定性签名（固定时钟下两次签名逐字节一致，跨语言可复现）
- ✅ 短密钥补齐规则与 mcp-auth 一致（<32 字节）
- ✅ 畸形 JWS（null/空/两段/非法 base64）拒绝
- ✅ `alg=none` 算法混淆攻击拒绝

**模块测试：mcp-a2a 43 个用例全绿（15 bridge + 7 jwt + 12 auth + 9 签名）；全仓编译通过。**
