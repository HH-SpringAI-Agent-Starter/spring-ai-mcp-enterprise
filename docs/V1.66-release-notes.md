## 一句话

V1.65 把治理推进到「能签字」。V1.66 遇到的是另一件事：**Azure APIM AI Gateway 公开预览、AWS AgentCore Gateway 五类扩展、腾讯云 v3.9.8（11-06 产品动态）、Celigo 11 月版，在一周内把工具注册 / 动态列工具 / 鉴权 / 限流 / HITL / 可观测全部做成了平台标配。**

所以今晚不写「我们也有治理」，而是做两件事：

1. **诚实复核定位**：交付一份能进标书的云网关能力对照 + 5 条买方问答，把差异化从「有没有治理」换到「**跨运行时签字 / 私有化合规工件 / 存量 Java 权限复用 / 连接路径准入**」四件云厂商结构上不做的事；
2. **把攻击面补齐**：`CVE-2026-119025` 证明代码可以在**工具列表出现之前**、经 OAuth discovery 到达 PowerShell 就执行 —— 零工具调用、零审批、零模型参与，工具级 guardrail 架构上看不见。新增客户端侧连接路径防护，并把 V1.65 遗留的两项 TODO 真正闭环。

> **金句（延续 V1.64/V1.65）**：协议负责连通、平台负责编排、云厂商负责托管，
> **而「谁对这次调用签字负责」只能由一层不绑定任何 Agent 平台、也不绑定任何云的治理层承担。**

## ⚠️ 诚实边界（延续口径，不要删）

- 本期**未改动 21 模块主代码**；`examples/` 是参考实现，不是已集成进 `mcp-server` 的生产 Bean。
