# 证券业招标首次把「MCP Server 工程能力」写成供应商资质门槛：广发证券征集公告逐条拆解，Java 工程师的机会清单来了

> 发布：2026-11-04 ｜ 掘金/CSDN SEO 稿 ｜ 关键词：MCP Server、企业招标、证券业大模型、MCP 治理、Java Spring AI、影子AI、MCPHub CVE

## 一、一条招标公告，把 MCP 从"技术名词"变成了"资质门槛"

2026 年 11 月初，广发证券采购平台挂出《2026 年企业微信持续建设项目 供应商征集公告》。这份面向集成商的预招标文件里，MCP 不再是"了解者优先"，而是被写进了**硬性资质要求**：

> "具备技能（Skill）工程化能力（定义、注册、编排、复用、版本管理与效果评测）及 **MCP Server 设计与开发适配能力（工具定义与描述、参数校验、鉴权与权限控制、调用限流、日志与可观测性）**"

括号里这五项，就是 MCP Server 的**工程能力五件套**。这也是可核验的证券业招标文本中，首次把 MCP Server 能力写成供应商准入门槛——不是加分项，是入场券。

建设范围同样清晰：**「智能体（Agent）+ 技能（Skill）+ MCP 工具接入」三层体系**——6 个场景智能体、十几个可复用技能，以及客户信息、资产/持仓/交易、业务准入规则、留痕中心等 MCP 工具接入。还有两条容易被忽略但最"金融"的要求：

- **数据权限按客户经理归属严格隔离**（多租户）
- **服务行为自动留痕、日志不可篡改**（审计）

## 二、这五项资质，每一条都对应一个工程模块

如果你在做（或想接）企业级 MCP 项目，可以把这五项当成需求清单自查：

| 招标资质原文 | 工程含义 | 开源实现参考 |
| --- | --- | --- |
| 工具定义与描述 | 工具注册中心、schema 管理 | 工具注册模块（注册/发现/版本） |
| 参数校验 | fail-closed 输入校验，防注入 | 网关参数校验层 |
| 鉴权与权限控制 | API Key/OAuth2.1 + Scope-ACL + HITL | 治理模块（RBAC/Scope/审批） |
| 调用限流 | RateLimit、配额、熔断 | 限流模块 |
| 日志与可观测性 | 审计日志、tracing、SIEM 导出 | 审计+监控模块 |

外加两条金融特供：**多租户数据隔离**（按归属隔离客户数据）与**防篡改审计日志**。这七件事做齐了，你交付的就不是一个 demo server，而是能过券商合规的"治理底座"。

顺便说：这个项目要求用采购方的 Dify/hiagent 平台开发 Agent——但 MCP 工具层是你自己的工程。**Agent 平台可以买，MCP 治理层必须自建**，这就是集成商的技术溢价空间。

## 三、同一天的第二只靴子：趋势科技"影子AI"报告

就在招标公告同期，趋势科技旗下 TrendAI 发布报告《代理式AI的影子工作流程》，给了两组可以写进任何标书的数字：

- 分析 **19,000 个开源 MCP 服务器仓库，约 20% 存在可被利用的漏洞**；
- 发现 **1,467 个对外暴露、完全没有鉴权机制的 MCP 服务器**；
- 2025 年已出现 **95 个 MCP 相关 CVE**，预估 2026 年 AI 相关 CVE 达 **2,800~3,600 个**；
- 新攻击范式 **Return-to-Tool（RTT）**：恶意指令藏进客服工单/文档/数据库记录，代理 AI 把它当工作要求，用自己**本来看似合法的权限**去偷验证权杖、加密客户资料。

翻译一下：企业接入 AI 代理的速度，已经超过它们的资安能见度——大量 MCP 服务器成了"影子AI"，不在资产清册里、不做鉴权、没人审计。**这正是招标方把"鉴权与权限控制、日志与可观测性"写进资质门槛的原因**：不是甲方懂行，是甲方被吓过。

## 四、第三只靴子：网关自己也会出洞

本周另一个值得 Java 工程师盯着的 CVE：**CVE-2026-120323（MCPHub）**。MCPHub 是一个自托管 MCP 网关/控制面，漏洞机制相当典型：

非管理员用户可以注册一个 OpenAPI 类型的 MCP server，并把 `passthroughHeaders` 配置成 `Authorization / Cookie / X-Api-Key`——这个配置没有被归类为特权操作。之后**任何其他用户（包括管理员）调用该 server 上的工具时，网关会把调用者请求里的这些头原样转发给攻击者的服务器**。管理员的 bearer key、session cookie，直接拱手送上。

结论很直白：**用了网关 ≠ 安全。网关本身需要治理增强层**——server 准入分级（谁能注册什么类型的 server）、egress 白名单（凭据能发往哪里）、凭据隔离（调用者凭据不出本域）。同周还有 Prefab UI/FastMCP 沙箱逃逸（CVE-2026-120338，CVSS 10.0）和 LobeHub 路径穿越（CVE-2026-120315，8.8），三连击再次验证一个规律：**官方 SDK 和现成组件都有洞，治理层必须自己焊**。

## 六、给 Java 工程师的三步行动

1. **对照五件套自查**：把你现有的 MCP Server（或计划写的）过一遍——工具 schema 有没有校验？有没有 Scope 级权限？限流在哪层？审计日志防不防篡改？差哪补哪。
2. **把治理做成默认能力而不是后补**：鉴权（OAuth2.1/Bearer 强制校验）、限流、HITL 审批、多租户隔离，这四件事在第一行代码就设计进去，成本最低。
3. **盯预招标窗口**：供应商征集公告→正式招标通常 30~60 天。MCP 治理能力现在是集成商的资质缺口，开源治理底座+行业案例是投名状。
