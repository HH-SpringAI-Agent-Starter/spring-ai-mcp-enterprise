# V1.12 发布说明 — Schema 级多租户隔离（mcp-tenant 升级）

> 发布日期：2026-08-27 | 版本：1.1.0 → 1.1.0（模块内增强，非破坏性新增，默认 `mode=row` 完全兼容 V1.11）

## 一、为什么做 Schema 级隔离

1. **V1.11（Row-level）的上层补完**：Row-level 靠「业务 SQL 显式带 tenant 列 + JdbcTemplate fail-closed 守卫」，适合共享表结构、按行隔离；Schema 级隔离把**物理边界**推到数据库层——每个租户一个独立 schema，天然防「忘写 tenant 列」的人为事故，是强合规场景（金融/政务/医疗）的硬要求。
2. **市场信号（承接 08-26 雷达）**：Sumo Logic Staff SWE（$207-243K）JD 明确要求 *multi-tenant isolation + 24x7 多租户服务 SLA*；行业分级把「Design multi-tenant MCP platforms」列为 Senior MCP Architect Tier-3 能力。**Row（V1.11）+ Schema（V1.12）双模式 = 投标单上「多租户」一栏从「有」变成「全」**。
3. **架构对称性**：V1.11 发布说明已规划 V1.12 Schema 隔离 → V1.13 实例隔离（独立数据库/连接池）。三档隔离（row → schema → instance）形成完整的多租户产品故事线。

## 二、新增能力一览（mcp-tenant）

| 组件 | 职责 |
|------|------|
| `TenantSchemaManager` | tenantId → schema 名映射（白名单校验 + 小写化 + `-`→`_`，防 SQL 注入）；方言检测（auto/postgresql/mysql/h2/generic，首次解析后缓存）；schema 自动创建（provision）+ 模板 DDL 落库 |
| `TenantSchemaDataSource` | 包装 DataSource，`getConnection()` 返回动态代理 Connection；在 `createStatement/prepareStatement/prepareCall` 前自动执行租户 schema 切换（`SET SCHEMA`/`SET search_path`/`USE`）；连接级缓存已切换 schema，重复语句零开销 |
| `InvalidTenantSchemaException` | 非法 tenantId（非 `[A-Za-z0-9_-]`、超 64 字符）直接拒绝，schema 标识符注入面封死 |
| `McpTenantProperties.Mode` | `row`（默认，V1.11 行为不变）/ `schema` 双模式切换 |
| `McpTenantProperties.Schema` | `prefix`（默认 `tenant_`）/ `dialect` / `provision-on-first-use`（默认 true）/ `template-ddl`（可选） |

### Fail-closed 语义（schema 模式）

- 无租户绑定 → 任何 Statement 创建直接抛 `TenantNotResolvedException`，跨租户泄漏在连接层被阻断；
- provision 默认开启：首次访问自动 `CREATE SCHEMA IF NOT EXISTS tenant_x`，并把模板 DDL（如建表语句）执行在**该租户 schema 内**（同一连接上先切换再执行，保证落对位置）；
- provision 幂等，模板 DDL 需自备幂等写法（推荐 `IF NOT EXISTS`）。

### 使用方式

```bash
# mcp-server 已内置依赖；启用 schema 模式（示例 profile 或合并进 application.yml）
mcp:
  tenant:
    mode: schema
    schema:
      prefix: tenant_
      dialect: auto          # 生产建议显式配置 postgresql/mysql
      provision-on-first-use: true
      template-ddl: "CREATE TABLE IF NOT EXISTS app_data(id BIGINT AUTO_INCREMENT PRIMARY KEY, payload VARCHAR(500));"
```

调用时与 V1.11 完全一致，无需改业务代码：

```bash
curl -H "Authorization: Bearer $TOKEN" -H "X-Tenant-Id: acme-corp" \
  http://localhost:8080/mcp/stateless
```

业务代码无感知（Schema 切换由数据源代理完成）：

```java
@Autowired TenantSchemaDataSource dataSource;  // 或直接用容器内 DataSource（已被包裹）

// TenantContext 由 McpTenantFilter 从 X-Tenant-Id 绑定，SQL 无需关心租户列
jdbcTemplate.query("SELECT * FROM app_data WHERE ...");  // 自动落在 tenant_acme_corp schema
```

## 四、与 V1.11 的兼容性

- 默认 `mode=row`：`TenantAwareJdbcTemplate` 行为、配置项、语义完全不变；
- `mode=schema` 时自动装配 `TenantSchemaManager` + `TenantSchemaDataSource`，Row 模式的 `TenantAwareJdbcTemplate` 不再注册（二选一，避免双重约束）；
- 两个模式共用 `X-Tenant-Id` 头约定与 `TenantContext`，业务切换成本为零。
