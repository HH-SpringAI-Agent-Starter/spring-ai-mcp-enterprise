# V1.24 发布说明 · 2026-09-13

## 版本主题

**可观测性治理开箱即用：内置 Prometheus 告警规则 + Grafana 自动 Provisioning 看板**

一句话：从 V1.7 起我们已暴露 OpenMetrics 指标端点，但「有了指标」不等于「能运营」。V1.24 把 **告警规则、看板、SLO 建议、排查手册** 一起补全，让 MCP Server 从「能跑」变成「能上生产、能被 SRE 接管」。

## 新特性

### 1. 内置 Prometheus 告警规则（`config/prometheus/alerts.yml`）

四组规则，直接对齐 `McpMetricsCollector` 导出的真实指标：

| 分组 | 规则 | 触发条件 |
|---|---|---|
| 工具 | `McpToolHighErrorRate` / `McpToolCriticalErrorRate` | 错误率 > 20%（5m）/ > 50%（15m） |
| 工具 | `McpToolLatencyHigh` / `McpToolLatencyCritical` | 平均延迟 > 3s（10m）/ > 8s（5m） |
| 网关 | `McpGatewayHighErrorRate` / `McpGatewayLatencyHigh` | 路由错误率 > 20% / 延迟 > 5s |
| 基础设施 | `McpServerDown` / `McpServerRestarted` / `McpTrafficDrop` | 抓取失败 2m / 构建信息变化 / 调用量骤降 |

错误率统一采用 `rate(errors) / clamp_min(rate(invocations), 1e-9)`，规避除零；`McpTrafficDrop` 用「当前 10 分钟速率 vs 1 小时前同期」识别 Agent 客户端异常。

### 2. Grafana 自动 Provisioning（`config/grafana/`）

- `provisioning/datasources/prometheus.yml`：启动即注册 Prometheus 数据源（固定 `uid=prometheus`，看板免手工绑定）；
- `provisioning/dashboards/dashboards.yml`：自动加载 `dashboards/` 目录；
- `dashboards/mcp-enterprise-overview.json`：**11 面板**总览看板——存活、工具数、累计调用/错误、整体错误率、网关延迟、按工具调用/错误速率、延迟曲线、网关路由曲线、工具健康明细三联表。

`docker compose --profile monitoring up -d` 一键起 Prometheus + Grafana + Node Exporter，看板自动出现。

### 3. 文档（`docs/observability-guide.md`）

- 指标体系逐项说明（含「聚合窗口」这一容易误读的点）；
- 接入企业既有 Prometheus 的配置样例（含 Bearer 鉴权）；
- SLI/SLO 起点建议 + 可用性/错误预算燃尽 PromQL；
- 「告警 → 排查动作」对照手册；
- 内置 REST 监控接口清单。

## 为什么这个版本对企业客户重要

近一周市场雷达显示，企业 MCP 岗位 JD 高频要求集中在「**可观测性 / 告警 / 限流 / 多租户 / 治理**」（Sumo Logic 的 MCP 平台岗、沃尔玛中国的 AI/MCP 网关岗、MintMCP 的 MCP 治理平台）。本版本把可观测性从「文档承诺」变成「仓库里能直接 `docker compose up` 验证的资产」，是可参与 POC/招标的实质加分项。

## 兼容性

- 纯配置/文档增量，**无 Java API 变更**，对 V1.23 及以前完全向后兼容；
- 指标名称与端点保持不变，已接入的企业 Prometheus 无需改动抓取配置；
- 仅在 `--profile monitoring` 下新增挂载，默认 `docker compose up -d` 行为不变。
