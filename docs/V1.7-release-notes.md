# V1.7 Release Notes — Spring AI MCP Enterprise

> 版本：V1.7 | 日期：2026-08-19 | 状态：已完成

## 版本说明

V1.7 是 **2026-07-28 无状态化规范「网关按操作限流 + 可观测性」的完整落地版**。V1.5/V1.6 把 `Mcp-Method`/`Mcp-Name` 标头变成了协议能力与观测数据，V1.7 补上了**执行面**：网关限流路由表（运行时按操作 QPS 管理）与 Prometheus 指标导出（对接 Grafana 生态）。

## 本轮变更内容

### 1. 🚦 网关限流路由表（GatewayRateLimitManager）
- **新增**：`mcp-core` 的 `GatewayRateLimitManager` — 按 `Mcp-Method` / `Mcp-Name` 双维度配置限流规则
- **规则语义**：`tools/call:*` 总限流、`tools/call:greet` 单工具限流、`tools/call:finance_*` 前缀通配组限流
- **匹配优先级**：方法精确 > 通配；同一方法下 name 精确(30) > 前缀通配(20) > 全通配(10)
- **无需解析请求体**：网关仅凭标头即可决策（2026-07-28 规范核心价值）
- **安全防护**：规则上限 256 条防配置失控；令牌桶实现；开关可运行时切换

### 2. ⚡ McpStatelessEndpoint 内置默认规则
- `tools/list` / `tools/listChanged`: 5 QPS（目录拉取防刷）
- `tools/call`: 100 QPS（总上限，可按工具覆盖）
- `ping`: 20 QPS、`initialize`/`server/discover`/`tools/discover`: 10 QPS
- 超限返回 **JSON-RPC -32029 "Rate limit exceeded"**

### 3. 🎛️ 限流管理 REST 端点（mcp-server）
```
GET    /api/mcp/v2/ratelimit/rules       — 规则列表
POST   /api/mcp/v2/ratelimit/rules       — 新增/更新（{"method","name","maxPerSecond"}）
DELETE /api/mcp/v2/ratelimit/rules?method=&name= — 删除
DELETE /api/mcp/v2/ratelimit/rules/all   — 清空
POST   /api/mcp/v2/ratelimit/toggle      — 开关（{"enabled":false}）
```
**无需重启**即可按操作调整 QPS，适合压测调优与故障应急。

### 4. 📈 Prometheus 指标导出
- **新增**：`GET /api/monitor/metrics/prometheus` — OpenMetrics 文本格式
- **指标**：
  - `mcp_tool_invocations_total{tool}` / `mcp_tool_errors_total{tool}` / `mcp_tool_latency_ms{tool}`
  - `mcp_gateway_invocations_total{method,name}` / `mcp_gateway_errors_total` / `mcp_gateway_latency_ms`
  - `mcp_build_info{version}`
- **标准语义**：counter/gauge TYPE 声明 + HELP 注释，Prometheus 可直接抓取，Grafana 即插即用
- **标签安全**：标签值转义（`\` `"` `\n`），确定性排序输出

### 5. 🧪 测试（新增 17 项）
- `GatewayRateLimitManagerTest`: 14 项（规则匹配优先级、通配符、限流语义、上限保护、开关）
- `McpStatelessEndpointTest` 新增 4 项（默认规则限流 429、精确规则覆盖通配、管理接口、清空放行）
- `McpMetricsCollectorTest` 新增 4 项（Prometheus 导出工具/网关指标、标签转义、空状态）
