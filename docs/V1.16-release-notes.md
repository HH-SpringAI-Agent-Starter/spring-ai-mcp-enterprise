# V1.16 发布说明 —— A2A 流式（SSE message/stream + task/resubscribe）+ securitySchemes 声明

> 发布日期：2026-09-01
> 核心主题：**让 A2A 网关支持实时流式调度 + 对外声明鉴权方案** —— 补齐 A2A v1.0 双协议网关最后一块能力拼图，并向 mcp-auth 打通迈出第一步。
> 版本基线：V1.15（MCP + A2A 双协议网关）→ V1.16

---

## 一、为什么做 V1.16

**V1.15 已让同一个网关同时讲 MCP 和 A2A 两种语言，但 A2A 侧还差"流式"与"鉴权声明"两块：**

1. **市场信号**：
   - A2A v1.0 规范里 `message/stream` / `task/resubscribe` 是 Agent 编排器的标准长连接语义（SSE），Google ADK / Azure AI Foundry / Bedrock AgentCore 等原生支持 A2A 的主播都默认用流式消费。
   - 大量招聘 JD 点名"**SSE 传输层 / Streamable HTTP / 实时事件流**"（Ampstek、OneSeven Tech、CriticalRiver MCP 岗均要求 JSON-RPC + SSE + Streamable HTTP + token 管理）。
   - `securitySchemes` 声明是 A2A v1.0+ 协议规定的鉴权协商入口——没有它，A2A 编排器无法得知该用 API Key 还是 OAuth2 来调用本网关，等于"裸奔但不自知"。

2. **结论**：V1.15 把工具注册中心一次建成、两种协议消费；V1.16 把 A2A 侧从"同步问答"升级为"实时流式调度"，并显式声明鉴权方案，让网关注入即被任何 A2A 编排器正确接入。

## 二、新增内容

### 1. SSE 流式端点（mcp-integrations/mcp-a2a）

| 方法 | 端点 | 说明 |
| --- | --- | --- |
| POST | `${base}/rpc/stream` | A2A v1.0 SSE 流式（`Accept: text/event-stream`） |
| —— | `message/stream` | 后台异步执行 MCP 工具，推送事件序列 |
| —— | `task/resubscribe` | 重放目标任务历史事件（含已完成任务），随后保持长连接 |

**事件类型（对齐 A2A v1.0 规范）：**
- `TaskStatusUpdateEvent`：working → completed/failed/canceled
- `TaskArtifactUpdateEvent`：工具结果产出 Artifact
- `MessageDeliveryEvent`：message/stream 最终投递的 agent 消息
- `TaskNotFoundEvent`：task/resubscribe 目标任务不存在

### 2. 新类与改动（mcp-a2a）

| 类 | 职责 |
| --- | --- |
| `A2aStreamEvent` (新) | SSE 流式事件模型（event + taskId + data） |
| `A2aBridgeService.streamTaskSend()` | 异步启动流式任务，事件写入历史并推送给订阅者（daemon 线程池，不阻塞 HTTP） |
| `A2aBridgeService.subscribe()` | 先同步重放历史 → 未终态挂接活跃订阅 / 终态立即 complete（解决"任务已完成、订阅来晚"竞态） |
| `A2aBridgeService.buildSecuritySchemes()` | 按配置声明 securitySchemes（api-key / oauth2 / none） |
| `A2aRpcController.rpcStream()` | SSE 端点，鉴权后分派 message/stream / task/resubscribe |
| `A2aAgentCard` | 新增 `securitySchemes` 字段 |
| `McpA2aProperties` | 新增 `streaming-enabled` / `stream-heartbeat-ms` / `security-scheme` / `oauth2-token-url` |

### 3. securitySchemes 声明（mcp-auth 打通第一步）

- **api-key**（默认，当配置了 `api-key` 且未显式指定 scheme）：`{ type: apiKey, in: header, name: X-A2A-Key }`
- **oauth2**：`{ type: oauth2, flows.clientCredentials.tokenUrl = 配置端点 }`（默认对接 mcp-auth `/oauth2/token`）
- **none**：空列表

Agent Card 的 `capabilities.streaming` 现跟随 `streaming-enabled` 配置（默认 true）。

### 4. 配置（mcp-server application.yml 注入）

```yaml
mcp:
  enterprise:
    a2a:
      enabled: ${MCP_A2A_ENABLED:false}
      streaming-enabled: ${MCP_A2A_STREAMING_ENABLED:true}
      security-scheme: ${MCP_A2A_SECURITY_SCHEME:}   # none | api-key | oauth2
      oauth2-token-url: ${MCP_A2A_OAUTH2_TOKEN_URL:}
```

## 三、测试

- `A2aBridgeServiceTest` 新增 6 个用例，共 **15 个用例全绿**：
  - agent card streaming=true 默认开启 + securitySchemes 空声明
