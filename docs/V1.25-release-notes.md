# V1.25 发布说明 · 2026-09-14

## 版本主题

**MCP Federation Gateway（联邦 MCP 网关）：一个入口，聚合所有下游 MCP Server**

一句话：从 V1.7 起我们是一个「企业级 MCP Server」；V1.25 之后我们同时是「MCP 网关」——把**任意多个**下游 MCP Server（内部部门服务、第三方平台、Python FastMCP 生态）拉进同一个治理平面，工具自动命名空间隔离，RBAC/限流/审计/Scope 全部复用。

为什么是它：本周市场雷达出现两个强信号——Sumo Logic（$207–243K）JD 原文写 "**federating with external and third-party MCP servers**"；MintMCP（Cowboy Ventures/Coatue 背书、Coursera/Arlo/Braze 在用）整家公司就是在做 **MCP Gateway**。联邦/聚合是平台型岗位的硬需求，而 Java 生态里几乎没有现成的联邦网关实现。

## 新特性

### 1. 新模块 `mcp-gateway`：联邦网关核心

```
mcp-gateway/
├── McpGatewayProperties             # 配置：mcp.enterprise.gateway.*（多上游，默认开启）
├── McpUpstreamStatus                # 上游运行状态（健康/工具数/上次同步/错误）
├── RemoteToolDescriptor             # 远程工具描述（tools/list 裁剪）
├── UpstreamMcpClient                # 上游客户端 SPI（ping/listTools/callTool）
├── client/StreamableHttpUpstreamClient   # Streamable HTTP / JSON-RPC 实现（JDK HttpClient，零依赖）
├── client/McpUpstreamClientFactory  # 客户端工厂 SPI（可替换私有协议）
├── executor/FederatedToolExecutor   # 联邦工具执行器（实现 McpToolExecutor → 治理自动继承）
├── manager/McpFederationManager     # 联邦编排（注册/刷新/失败保留/禁用移除）
└── manager/McpGatewayAdminController# 管理 REST API
```

### 2. 联邦工具 = 一等公民（治理自动继承）

联邦工具通过 `FederatedToolExecutor implements McpToolExecutor` 注册进既有的 `McpToolManager`，因此**自动获得**：RBAC 角色校验、RateLimit、审计日志、工具级 Scope 授权（V1.19）、健康检查、调用统计——对 Agent/业务系统完全透明，仿佛本地工具。

本地工具名规则：`<prefix>__<remoteToolName>`（prefix 缺省 = 上游 name），跨上游命名空间隔离，杜绝工具名冲突。

### 3. 生产级同步语义

| 场景 | 行为 |
|---|---|
| 上游 `enabled=false` | 移除其全部联邦工具，保持未注册 |
| 同步失败 | **保留已注册工具**（可用性优先），标记 unhealthy + 错误信息 |
| 重新同步 | 先摘旧、后挂新，无残留、无中断 |
| 上游未知 | 返回语义化错误（404 风格） |
| 启动时 | `sync-on-startup=true`（默认）ApplicationRunner 全量同步 |

### 4. 零依赖 Streamable HTTP 客户端（MCP 2026-07-28）

- 纯 JDK `HttpClient`，无额外依赖；
- 自动完成 `initialize` → `notifications/initialized` → 目标方法的握手序列；
- 响应兼容**单 JSON** 与 **SSE（`data:` 行）**两种形态；
- `api-key` 配置后自动透传 `Authorization: Bearer`；
- `tools/call` 结果归一化：`structuredContent` 优先，`isError` → `success=false`，text content 兜底。

### 5. 管理 REST API

```
GET    /api/admin/gateway/upstreams                 # 所有上游状态（健康/工具数/上次同步）
POST   /api/admin/gateway/sync                      # 全量刷新联邦工具
POST   /api/admin/gateway/upstreams/{name}/sync     # 刷新单个上游
DELETE /api/admin/gateway/upstreams/{name}/tools    # 移除该上游全部联邦工具（下线）
GET    /api/admin/gateway/health                    # 聚合健康视图
```

## 配置示例

```yaml
mcp:
  enterprise:
    gateway:
      sync-on-startup: true          # 启动自动同步（默认 true）
      upstreams:
        - name: hr                   # 工具前缀 = hr
          url: http://hr-mcp:8080/mcp
          api-key: ${HR_MCP_API_KEY:}
          enabled: true
        - name: finance
          url: http://finance-mcp:8080/mcp
        - name: legacy               # 被收购的旧系统，先禁掉
          url: http://legacy:8080/mcp
          enabled: false
```

## 为什么这个版本对企业客户重要

1. **平台岗 JD 的硬性要求**：Sumo Logic「federating external MCP servers」、MintMCP「MCP Gateway」——V1.25 让仓库直接拥有可演示的联邦能力，而不是文档承诺；
2. **并购/整合叙事的工程支撑**：企业收购系统后，遗留 MCP 服务用 `enabled: false` 一键下线，新系统直接聚合——`/api/admin/gateway/upstreams/{name}/tools` 就是「整合控制面」；
3. **无侵入接入既有生态**：Python FastMCP、Spring AI 官方 server、第三方 SaaS MCP——只要是 Streamable HTTP，都是我们的上游。Java 网关 + 异构上游 = 真正的「企业统一 Agent 入口」。

## 兼容性

- **纯新增模块**：不动既有任何模块的 API；`mcp-gateway` 默认开启，`mcp.enterprise.gateway.enabled=false` 或不加依赖即可整体关闭；
- 联邦工具注册进既有 ToolManager，对 V1.23 Spring AI Tool Bridge / V1.19 Scope 等全部兼容；
- 22 个新测试全绿（HTTP 桩服务器验证真实 JSON-RPC 往返，无外部网络依赖）。
