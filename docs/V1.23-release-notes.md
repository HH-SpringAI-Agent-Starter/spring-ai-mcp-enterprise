# V1.23 发布说明 · 2026-09-12

## 🎯 版本主题

**Spring AI 工具桥接：把已有的 `@Tool` 工具，零改造变成企业级 MCP 工具**

## ✨ 新特性

### 新增模块 `mcp-springai-tools`（Spring AI Tool Bridge）

一句话：扫描 Spring 容器里的 Spring AI 工具，自动包装成企业 `McpToolExecutor` 注册进 `McpToolManager`，**自动继承 RBAC 权限、RateLimit 限流、审计日志、工具级 Scope 授权（RFC 6750）、健康检查、超时控制**——业务代码零改动。

**三类工具源全覆盖：**

1. `@Tool` 注解方法的 Spring Bean（Spring AI 最主流写法，自动转 `MethodToolCallback`）；
2. `ToolCallback` Bean（含 `FunctionToolCallback`）；
3. `ToolCallbackProvider` Bean（含 Spring AI MCP Client 动态发现的远端工具，`FunctionCallback` 自动收窄为 `ToolCallback`）。

**核心实现：**

| 类 | 职责 |
|---|---|
| `SpringAiToolCallbackExecutor` | `ToolCallback` → 企业 `McpToolExecutor` 适配器：定义侧做 JSON Schema 转换 + 治理字段补齐；执行侧做参数序列化/结果归一化 |
| `SpringAiToolCollector` | 三类来源发现 + 按最终注册名去重（重名 WARN 不静默覆盖） |
| `SpringAiToolsAutoConfiguration` | `SmartInitializingSingleton` 时序注册（等所有单例就绪），`@AutoConfigureAfter` 企业自动配置，`mcp.springai-tools.enabled=false` 可整体关闭 |
| `SpringAiToolsProperties` | 前缀 `mcp.springai-tools.*`：name-prefix / category / default-roles / required-scopes / timeout-ms / rate-limit-per-second 等 |

**工程细节（被测试抓出的真实 bug）：**

- Spring AI M6 对 `String` 返回类型做 **JSON 双重编码**（`{"city":"北京"}` → `"{\"city\":\"北京\"}"`），适配器用 `readTree` 归一化：文本节点二次解析 → Object/Array 直接转换 → 解析失败原文透传。
- Spring 6.x 起 `DefaultListableBeanFactory.registerSingleton` 不再生成 BeanDefinition，收集器合并 `getBeanDefinitionNames()` + `getSingletonNames()`，保证两类容器场景都扫得到。

**配置示例：**

```yaml
mcp:
  springai-tools:
    enabled: true
    name-prefix: ""          # 如 "sa_" 避免与内置工具重名
    category: springai
    default-roles: "admin,user"
    rate-limit-per-second: 10
```
