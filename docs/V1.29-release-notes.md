# V1.29 Release Notes — 2026-09-20

## 版本主题：Governance AuditSink JDBC 化（治理审计事件落库）+ 市场雷达 09-20

> 一句话：**把 V1.26 的审计从「内存环形缓冲 + SLF4J 日志」升级为「可查询、可取证、跨实例可见的审计轨迹」**
> —— 治理模块在 V1.28 解决了「审批状态落库」，V1.29 补齐「审计事件落库」，HITL 闭环从此全程留痕。

## 变更内容

### 1. 新增 `JdbcGovernanceAuditSink`（mcp-governance，核心）
- **背景**：V1.26 的 `InMemoryGovernanceAuditSink` 只把审计事件放在单个 JVM 内存里（有界环形缓冲 + SLF4J）。企业合规场景两个缺口：
  1. **重启/滚动发布即丢失**：无法回答「上周谁在什么时候调过 finance_transfer？」这类取证问题；
  2. **多实例各自为政**：K8s 多副本下每条事件只存在于处理它的那个 Pod，审计员没有统一全局视图。
- **实现**：审计事件持久化到单表 `mcp_governance_audit`（可自定义表名），
  保持 V1.28 `JdbcApprovalStore` / V1.22 `JdbcSkillRegistryStore` 的设计约束——
  **方言无关**（只用 `CREATE TABLE IF NOT EXISTS`/`INSERT`/`SELECT` 绑定参数，
  避免 MERGE / FETCH FIRST / LIMIT 等跨库差异语句；H2/MySQL/MariaDB/PostgreSQL/SQL Server 直接可跑）。
  时间戳 epoch millis，脱敏后参数 JSON 存 VARCHAR。
- **语义**：
  - **只写不删**：审计是合规资产，只 INSERT + SELECT，不提供 DELETE/UPDATE（防篡改）；
  - **fail-soft 写入**：单条落库失败记录 WARN 并继续——审计是观察者，不是关键路径，
    绝不让审计链路打挂业务调用；
  - **近实时双写**：落库同时保持 SLF4J 输出（`log-to-slf4j` 可关），grep 日志与 SQL 查询两路并存；
  - **值级截断**：字符串参数截断到 400 字符再序列化，保证落库 JSON 始终合法可反序列化；
  - **同毫秒排序 tiebreaker**：新增 `seq` BIGINT 列，`ORDER BY ts DESC, seq DESC` 保证确定性排序。

### 2. 自动配置 store 选择（`audit.store=memory|jdbc`）
- `mcp.enterprise.governance.audit.store=jdbc` + classpath 有 `JdbcTemplate` →
  自动创建 JDBC sink 并幂等建表（`init-schema` 可关，表名 `table` 可配）；
- 配置了 `store=jdbc` 但没有数据源 → 打 WARN 回退内存实现（进程不挂，可用性优先）；
- 未配置 → 维持 V1.26 内存行为（零依赖，默认值不变）。

### 3. 测试：governance 模块 43 个全绿（新增 8 个）
- 新增 `JdbcGovernanceAuditSinkTest`（H2 内存库）：建表幂等、record/recent 往返、
  时间倒序（含同毫秒 seq tiebreaker）、JSON 特殊值往返（长字符串/浮点/布尔/嵌套 List）、
  recent limit、count、null 事件忽略、超长参数值级截断为合法 JSON、fail-soft（坏表不抛异常）。
- 既有 35 个 governance 测试保持全绿（`mvn -pl mcp-governance test` 通过）。

## 部署配置速览

```yaml
mcp:
  enterprise:
    governance:
      approval:
        store: jdbc          # V1.28 审批状态落库
        table: mcp_approval_requests
      audit:
        store: jdbc          # V1.29 审计事件落库
        table: mcp_governance_audit
        init-schema: true
        log-to-slf4j: true
```

**合规取证链路全打通**：审批请求表（谁批的、何时批的）+ 审计事件表（每次判定的完整轨迹）
—— 应对企业安全团队「MCP 调用到底发生了什么」的最短答案。
