# V1.32 Release Notes — 治理审计 → HTTP/SIEM 实时事件流导出（零外部依赖）

> 发布日期：2026-09-28 ｜ 版本：1.1.0（mcp-governance 模块）
> 主题：**让治理审计从「落库可查」进化到「事件发生时近乎实时到达 SOC」**

---

## 一句话

V1.29 让审计**落库**（JDBC 可查），V1.30 让审计**可检索/导出/清理**（运营闭环），V1.31 让审计**挂上调用链**（traceparent），
V1.32 让审计**实时流向安全运营中心**——`audit.store=http` 把每条治理判定批量异步推送到
Splunk HEC / Elasticsearch / Kafka REST Proxy / 任意 webhook，**全程只用 JDK 原生 HttpClient，零新增依赖**。

## 新增内容

### 1. `HttpGovernanceAuditSink`（mcp-governance，零外部依赖）

- 事件先入本地队列，攒够 `http-batch-size`（默认 50）立即批量 POST（JSON 数组），
  未攒满则由守护线程按 `http-flush-interval-ms`（默认 5s）定时兜底发送；
- 每个事件含完整治理字段：`timestamp/tool/tier/caller/decision/approvalId/arguments/message/traceId/spanId`
  （V1.31 的 trace 关联字段原样透传，SIEM 侧可直接 join 调用链）；
- **fail-soft**：发送失败仅 WARN + 事件保留本地队列重试（水位 `max-events×10` 防 OOM），
  绝不抛异常打挂业务调用（审计是观察者，不是关键路径）；
- **本地可查视图保留**：`recent()/search()/deleteBefore()` 与内存实现同语义，管理 REST API 零改动；
- **诊断指标**：`sentCount()/failedCount()/pendingCount()` 便于运维观测积压；
- **优雅关闭**：`close()` 触发最终 flush（配合 Spring DisposableBean，停机尽量不丢积压）。

### 2. 配置扩展（`McpGovernanceProperties.Audit`）

```yaml
mcp:
  enterprise:
    governance:
      audit:
        store: http
        http-url: http://your-siem:8088/services/collector/event   # Splunk HEC / Kafka REST Proxy / webhook
        http-batch-size: 50
        http-flush-interval-ms: 5000
        http-timeout-ms: 3000
        http-headers:
          Authorization: Splunk xxxxx-xxxx
```

- `store=http` 但 `http-url` 为空 → 自动回退内存实现并告警（不静默失败）；
- 附加请求头支持任意键值（认证/租户标识/路由头）。

### 3. 自动配置（`McpGovernanceAutoConfiguration`）

- `mcpGovernanceAuditSink(...)` 新增 `store=http` 分支，日志输出目标端点与批大小；
- 其余分支（memory / jdbc）行为完全不变，向后兼容。

## 使用方式

```bash
# 1) 配置 store=http 后启动应用，治理判定自动实时推送 SIEM
# 2) 本地仍旧可查（管理 API 不变）
curl "http://localhost:8081/api/admin/governance/audit?decision=DENY&limit=10" \
  -H "Authorization: Bearer $TOKEN"

# 3) 诊断：sink 计数可在自定义 Actuator 端点暴露（sent/failed/pending）
```

## 为什么现在做这个（市场信号）

- **企业 JD 中 observability/SIEM 成为 MCP 岗位高频硬技能**：Sumo Logic Staff MCP Engineer（$207K-243K）明确要求
  「observability into MCP interactions + rate limits/quotas」；Intellias Python MCP Engineer 要求 OpenTelemetry；
  WhiteCoat（新加坡医疗独角兽）MCP Engineer 要求日志/监控/追踪全链路；
- **2026 企业 MCP 采用进入「生产化」阶段**：调研机构与厂商一致指出 2026 企业 MCP 采购的四大阶段中
  「Monitoring and observability」是仅次于安全集成的第二阶段，审计事件实时入 SIEM 是刚需；
- **Kafka 是 MCP 后端 JD 高频词**（Mid-level Java Engineer MCP 明确要求 Kafka consumers），
  本实现让审计事件零依赖直达 Kafka REST Proxy，正面对齐技能图谱。
