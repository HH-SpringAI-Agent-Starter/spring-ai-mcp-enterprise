# V1.26 发布说明 · 2026-09-17

## 版本主题

**MCP Governance（治理模块）：给 Agent 的"手"装上人工审批闸门**

一句话：从 V1.25 起我们解决了「MCP Server 怎么连、怎么聚合」；V1.26 解决企业最担心的
**「Agent 拿到工具后谁来负责」** —— 高风险工具（转账/删库/发信/部署）不再由 Agent 一言而决，
而是先进入**人工审批队列（Human-in-the-Loop）**，批准后颁发**一次性令牌**才能执行；
全程带**风险分级**与**敏感数据脱敏审计**，对齐 OWASP MCP Governance & Risk Project。

为什么是它：企业采购 MCP 平台时，安全评审会几乎必问三个问题——
①"高权限工具 Agent 能直接调？" ②"审计日志里有手机号/身份证/密钥？" ③"谁批准的这次调用？"
V1.26 用一套配置把三个问题全部答掉，且**默认灰度（enforce=false）零侵入**，验证后再强制。

## 新特性

### 1. 新模块 `mcp-governance`：人类在环审批（HITL）

```
mcp-governance/
├── RiskTier                          # T0–T4 风险分级（OWASP 五级模型对齐，宽容解析 T3_WRITE/3）
├── McpToolRiskClassifier             # 工具分级：显式 tool-tiers > 分类语义 > 关键词启发式 > 默认 T2

├── ApprovalRequest / ApprovalStore   # 审批模型 + 存储 SPI

├── McpApprovalService                # 创建/批准/拒绝/一次性消费/否认重放/过期惰性清理
├── McpGovernanceGuard                # 判定核心（Fail-closed）
├── SensitiveDataRedactor             # PII/密钥脱敏（邮箱/身份证/银行卡/手机号/密钥键值，递归 Map/List）
```

### 2. 审批 = 一次性令牌（防重放）

`PENDING → APPROVED → CONSUMED` 完整状态机：

- 批准后调用方携带 `X-MCP-Approval-Id` 重试，校验通过即消费，**同一令牌不可二次使用**；
- 工具名 / 调用方一致性校验：审批的是 `finance_transfer`，拿来调 `db_execute` → 拒绝；
- 非法流转抛异常而非静默覆盖（对已批准记录再批准 = IllegalStateException）；
- 默认 15 分钟有效期，`sweep()` 惰性清理过期 PENDING。

### 3. Fail-closed 语义

| 场景 | 行为 |
|---|---|
| 等级命中 `deny-tiers` | 直接拒绝（硬闸门，不给审批机会） |
| 需审批但审批服务关闭 | **拒绝**（approval_unavailable，拒绝降级放行） |
| 令牌过期/工具不匹配/调用方不匹配 | 拒绝（approval_invalid） |
| 模块 `enabled=false` | 全部放行（向后兼容） |
| 非法工具等级配置 | 警告 + 忽略该项，启发式兜底（不静默降级安全级别） |

### 4. JSON-RPC 协议正确拦截

- 拦截响应保持 **HTTP 200 + JSON-RPC error**：`-32092 approval_required` / `-32093 governance_denied`，
  MCP 客户端可正常解析并拿到 `approvalId` 走审批流；
- 非 `tools/call` 报文（initialize / tools/list / ping）直接透传；
- `CachedBodyHttpServletRequest` 请求体重放，拦截判定后原样交回下游；
- 调用方身份解析：`X-MCP-Caller` → `X-Client-Id` → `X-Tenant-Id` → Bearer 哈希 → anonymous。

### 5. 敏感数据脱敏（对齐 Tyk 采购清单 "real-time PII/PHI redaction in transit"）

- 内置规则：邮箱 / apiKey·secret·password·token·credential 键值 / 身份证18位 / 银行卡16-19位 / 手机号；
- Map 整键打码：`{"password":"hunter2"}` → `{"password":"***"}`；
- 审批队列与审计事件中的参数**全部为脱敏后内容**，安全团队可放心导出日志。

### 6. 管理 REST API + 策略视图

```
GET    /api/admin/governance/approvals?status=PENDING   # 审批列表
GET    /api/admin/governance/approvals/{id}             # 详情
POST   /api/admin/governance/approvals/{id}/approve     # 批准
POST   /api/admin/governance/approvals/{id}/reject      # 拒绝
GET    /api/admin/governance/stats                      # 统计
GET    /api/admin/governance/audit?limit=50             # 审计事件
GET    /api/admin/governance/policy                     # 当前生效策略（灰度核查用）
```

### 7. 灰度优先的装配设计

出厂默认 `enforce=false`：模块只做**登记 + 审批入队 + 审计**，不拦截任何调用，
企业可在真实流量下核对分级是否准确；确认后 `enforce=true` 一键开启强制。

## 配置速览

```yaml
mcp:
  enterprise:
    governance:
      enabled: true          # 总开关（默认开）
      enforce: false         # 强制模式（默认关 = 灰度登记）
      require-approval-tiers: [T3, T4]
      deny-tiers: []         # 硬闸门等级
      tool-tiers:            # 显式覆盖（生产必配）
        finance_transfer: T4
      approval:
        enabled: true
        ttl-seconds: 900     # 审批有效期
      redaction:
        enabled: true
      audit:
        max-events: 2000
```
